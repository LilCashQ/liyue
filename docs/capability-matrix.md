# 能力矩阵（M0 实测）

本文件的数据由 `tools/capmatrix` 直接对内置的 cubiomes 快照探测生成，不使用任何推测值。

- cubiomes 快照：`Cubitect/cubiomes`，提交 `e61f90580cbdd883214a8054670dacae655e59c0`
- 群系探测：`setupGenerator` + `applySeed` + `getBiomeAt(scale=4, x=0, y=63, z=0)` 返回非负值
- 结构探测：`getStructureConfig(type, mc, &conf)` 返回非零
- 要塞探测：`initFirstStronghold` + `nextStronghold` 返回正值

复现：

```bash
tools/build-host-tools.sh
./build/capmatrix > build/capability.csv
python3 tools/capmatrix/render_matrix.py build/capability.csv
```

## 基岩版调研结论（M0）

| 候选 | 最近更新 | 结论 |
| --- | --- | --- |
| `reedacartwright/cubiomes`（bedrock 分支） | 2021-08-07 | 基于 1.17 之前的代码，用当前工具链编译失败（如 `setSeed` 未声明），无法覆盖 1.18+，不采用 |
| `Earthcomputer/bedrockified` | 2019-06-26 | Java 版研究模组，不是可链接的生成库，不采用 |
| `bedrock-dev/MCBEStructureFinder` | 2025-07-19 | 仅结构查找，没有群系生成；许可证与接口需进一步评估 |

**结论：M0 判定基岩版「暂不支持」**，不做硬接。M1 在版本选择器与能力矩阵中明确标注，避免用户误以为可以生成基岩版地图。后续若要支持，需要先找到可验证的基岩版群系算法实现，并用基岩版客户端数据做一致性验证。

## 验证记录

### JNI 与直算对照

`tools/refgrid` 直接调用 cubiomes 输出 64×64 网格（4 方块/格，格心采样，y=63），与 Kotlin → JNI 路径的输出做 FNV-1a 校验和比对。

| 版本 | 维度 | 种子 | 校验和 |
| --- | --- | --- | --- |
| 1.16.5 | 主世界 | 0 | `e4104c1ae74f051c` |
| 1.18.2 | 主世界 | 0 | `4122c7647fb60863` |
| 1.20.6 | 主世界 | 0 | `30db1fce324ca386` |
| 1.21.3 | 主世界 | 0 | `30db1fce324ca386` |
| 1.20.6 | 下界 | 0 | `24975a39563d4365` |
| 1.20.6 | 末地 | 0 | `0d21a6c797df8383` |
| 1.21.3 | 主世界 | 12345 | `00c1d5ca562324dc` |
| 1.20.6 | 主世界 | -4172144997902289642 | `551efd310c26d039` |
| 1.21.3 | 主世界 | 0（256×256 网格） | `4a67f6db382ad668` |

9 组基准全部通过（`BiomeFixtureTest`），说明 Kotlin 与 JNI 的坐标、版本、维度映射与直算路径完全一致。

主机侧耗时（C 直算，aarch64 容器）：64×64 格约 56 ms，256×256 格约 0.81 s。M1 的 512×512 tile 目标需要在此基础上做分块与并行优化。

### 原版服务端地面真值（关键验收）

M0 用原版 Minecraft 1.20.1 服务端生成 seed=0 的 256×256 方块区域（`forceload -128 -128 127 127`），保存后直接解析 Anvil 区块的 `biomes` 调色板，得到 y=63 的 64×64 格群系，与本项目 JNI 输出逐点比对：

- **一致率 99.83%（4089 / 4096 格）**，高于 99% 验收线。
- 7 个不一致点均位于群系交界处，属于边界采样差异；1.20.1 与 1.20.6 的世界生成一致，此项比对使用 `MC_1_20_6`。
- 该比对已固化为 `VanillaAgreementTest`，基准文件在 `core/seedgen/src/test/resources/vanilla/`。

复现命令：

```bash
tools/build-host-tools.sh
./build/refgrid 0 25 0 -128 -128 64 63 > build/grid.txt
python3 tools/mcserver/parse_biomes.py <服务端>/world/region -128 -128 64 4 build/vanilla.csv
python3 tools/mcserver/compare_grids.py build/vanilla.csv build/grid.txt
```

### 上游回归向量

cubiomes 自带 `testGeneration()` 对 1.0–1.20 的 14 个版本有固定校验和，本项目快照全部通过；Beta 1.8 的期望值在上游数组中为占位 `0x00000000`，实测不匹配，该版本不在里悦的支持范围内，因此不作为验收项。

复现：`tools/build-host-tools.sh && ./build/upstream-check`。

### 与 cubiomes-viewer 的对照说明

cubiomes-viewer 是 Qt 桌面程序，本项目所在的无图形容器无法运行其 GUI；且其内部同样链接 cubiomes，直接对照只能验证封装一致性。因此 M0 改为三条路径：上游回归向量、直算对照，以及**原版服务端地面真值**（见上）。第三条能发现 cubiomes 自身与原版游戏的偏差，是最有说服力的一条。

## 采样语义（实现备注，已修正）

cubiomes 的 `genBiomes` 在不同版本下语义不同。M0 初期按“1.18+ 用 scale=16”实现，实测只有 39% 与原版一致——因为 `scale > 4` 会跳过 voronoi 抖动，属于快速近似。正确做法是：

- 1.17 及更早的主世界：`scale=4`，坐标为群系坐标（1 格 = 4 方块），可直接使用。
- 1.18 及以后的主世界、以及下界/末地：先生成**方块分辨率**的 `scale=1` voronoi 精确图，再按 4×4 取格心降采样。
- `genBiomes` 的 `scale > 4` 在 1.18+ 会跳过 voronoi 抖动并退化为逐格噪声（实测相邻格几乎不相关），不能作为地图数据源；缩小视图改为在每个粗网格中心调用 `getBiomeAt(scale=1)` 逐点采样。
- 粗采样每格只取一个点，小于格宽的群系（河流、海滩等）会被混叠成棋盘状纹理，这是地图缩小时的预期行为；放大后恢复 4 方块精度。
